# Integration checklist

- [ ] Commitment is durably published before entries and any seed-dependent information.
- [ ] For a module whose steps consume player decisions, the **seed pre-commitment** is published before the round accepts its first decision, and the settlement transcript's choice log is the one the round actually played.
- [ ] For the permutation module, the `PermutationBook` is bound to the **published** round commitment before its first `place`, and that value is the one durably published — the module enforces commitment-before-first-bet within a book instance and cannot see whether the value was ever published, so binding a commitment published afterwards passes every check and provides none of the protection.
- [ ] For every module, the published round passed to `book.restore(definition, snapshot, publishedBinding)` is read from the **published-round record, not from the snapshot store**. `restore()` requires the argument and accepts `null` only for a genuinely unbound snapshot, but a host that reads both values from one store has re-pointed nothing and defended nothing: a whole-round rewrite is consistent, cheap and undetectable in process (ADR 0011; `docs/modules/permutation.md` §9.1). Reads from the two must be independently authenticated.
- [ ] **The permutation snapshot store is authenticated, and this item is not satisfied by the one above.** The published-round argument closes the whole-round re-point and nothing else. It does not bind the ticket: a forger with write access to the store can add a line that was never placed, delete one that was, or change a stake, mint the matching `place` receipt with the exported `commandFingerprint`, and re-seal the checksum — `restore()` accepts it _while the caller passes the correct published round_ (`docs/modules/permutation.md` §9.2, executed in `tests/security/snapshot-mutation.test.ts`). A deployment that satisfied only the previous item still restores fabricated payouts. Satisfy this with integrity-protected storage the game server cannot write to unilaterally, **or** by binding ticket and settlement under an operator key — the Ed25519 receipt core in `src/modules/permutation/aether/receipt.ts`, per `aether-order/docs/ENGINE.md` §7.6/§7.8 — and reconciling the restored book against a receipt the player also holds.
- [ ] Seed generation/grinding controls, key custody, rotation, reveal timing, and retention are documented.
- [ ] Module ID/version, definition ID/version/fingerprint, and all wire schema versions are persisted per round.
- [ ] The definition passes `reveal-conformance` with retained machine-readable output.
- [ ] Player/tenant authorization and wallet transaction are outside but atomic with the engine receipt.
- [ ] Every claim command uses the authoritative current belief state and the exact expected step revision.
- [ ] Every applied step is **derived by the host from the sealed truth** — for `sequential-cards`, by `deriveRevealSteps()` against the sealed deal — and never taken from a client or reconstructed by hand. A book holds no seed, so it validates a step as public record and cannot establish that it came from the committed deal; a fabricated but well-formed step is applied, and a mid-round liquidation credits against it before settlement can refuse the round.
- [ ] Under `pricing.rounding: 'stochastic'`, the round's **rounding tape** is derived by the host with `deriveRoundingSeed()` from the sealed round seed and passed to `open()`, and it is treated as a **round secret until settlement**, exactly like the seed it comes from. A uniform draw in `[0, d)` is a function of `d`, so a party who learns the tape early can compute the draw for each claim a decision window offers and take the branch that pays the extra credit. The edge is bounded by one credit per credit event and is largest at the minimum stake. The snapshot carries the tape, so this is part of the snapshot-storage obligation above and not separate from it.
- [ ] Under a declared `dormancy` policy, the **window is measured by the host** and asserted to `settleDormant()` as `elapsedSeconds`. The module has no clock: it refuses a settlement below the declared window, refuses an early reason the definition does not declare, and refuses a round still before its first reveal — but it cannot check that the seconds were measured, that the window started when the board became decidable, or that an account really changed state. A host that asserts a window it did not measure settles a live round at a fair price at a moment of its own choosing. Record the reason with the settlement, credit before notifying, and never present a system settlement as the player's decision.
- [ ] Idempotency key is scoped by player and round in durable storage; payload mismatch is a conflict.
- [ ] Settlement accepts only a verified seed and transcript and cannot run before every step is applied.
- [ ] Snapshot storage is authenticated; restore failures quarantine rather than repair balances silently.
- [ ] Cap basis and liquid value reconcile against wallet history after every action, and every stake is classified as external or recycled at the wallet boundary — a recycled stake that is recorded as external raises the round's ceiling.
- [ ] Ride/continuation has a separately reviewed state machine and economics model.
- [ ] Load, reserve, RNG, game math, jurisdiction, responsible-play, and certification reviews cover the deployed configuration.
