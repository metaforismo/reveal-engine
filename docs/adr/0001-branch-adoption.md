# ADR 0001 — What to adopt from the adoption-bridge and package-fixture branches

- **Status:** accepted
- **Date:** 2026-07-29
- **Context branch:** `platform/core`
- **Reviewed:** `origin/agent/black-signal-adoption-bridge` (`2e837bc`) and
  `origin/codex/package-compatibility-fixture` (`c791102`, a superset of the
  former)

## Context

Both branches predate the platform restructuring. Together they add ~1,500 lines
of source, a 101,478-line JSON corpus, a new `src/compatibility/` top-level
module, a third CLI, and a re-derived continuation policy. The restructuring
brief is the opposite direction: make BLACK SIGNAL stop being the engine's
spine. So each piece was judged on whether it is _platform_ work or _migration_
work.

## Decisions

### Adopted — `deriveMaxContinuations` (`src/core/continuation.ts`)

Pure exact-rational helper: the largest ride count `n` for which `r^(n+1)` still
clears an RTP floor. No BLACK SIGNAL coupling, no dependencies, and it replaces
a hand-tuned constant with a derived one. Moved into core alongside
`payments.ts`; the branch's `tests/continuation-policy.test.ts` came with it.

Consequence: `blackSignalReference` now derives `maxRides = 2` instead of
declaring `1`, which is a replay-visible economic change, so its
`adapterVersion` moves `1.0.0 -> 1.1.0` and its fingerprint changes. That is
exactly what the compatibility rule in `docs/api-contract.md` requires. No
frozen fixture depends on this adapter (`transcript-v1` / `transcript-v2` are
both `binary-beacon-conformance-v1`), and the known-answer proof vector is
unaffected.

### Adopted — real-install package smoke (`scripts/package-smoke.mjs`)

The codex branch replaced a `dist/`-relative import check with `npm pack` plus
an install of the tarball into a throwaway consumer, importing every subpath
through the package's own `exports` map. That catches a broken export map, which
the previous version could not. Adopted as technique, rewritten for the new
subpath list (`./modules`, `./modules/progressive-market`) and without the
corpus assertions.

### Skipped — `src/compatibility/` and `black-signal-v1.json`

The compatibility corpus is a well-built shadow-comparison harness: 64 vectors,
4,096 economic cases, classified deltas, an integrity digest, and a CLI. It is
also 1,450 lines of code plus a 101,478-line fixture whose entire purpose is
comparing this engine against one legacy title implementation.

Skipped, for three reasons:

1. **It is migration evidence, not platform architecture.** Shipping it as a
   top-level `src/compatibility/` surface would re-install BLACK SIGNAL at the
   centre of the engine at the exact moment we are removing it from there.
2. **It cannot be re-derived here.** The corpus was captured from a source
   revision of the title repository that this repository does not contain and
   cannot reproduce. A frozen artifact nobody can regenerate is a liability in a
   repository whose whole claim is "verifiable by re-derivation".
3. **It bloats a now-public repository** by roughly 3 MB of single-title data
   with no value to any other module.

The _idea_ is kept: per-module golden vectors are part of the conformance-hook
contract in `docs/lifecycle-modules.md`, and the frozen wire fixtures
(`transcript-v1`, `transcript-v2`) remain verified by re-derivation on every
run.

Where it should live instead: the title's own repository, or a separate
`reveal-engine-compat` artifact repository, generated by the capture script and
consumed during a shadow-mode migration. If it is revived, it belongs behind a
`./modules/progressive-market/compat` subpath, not at the engine root.

### Skipped — the rest

- New error codes `INVALID_COMPATIBILITY_CORPUS` /
  `COMPATIBILITY_INTEGRITY_MISMATCH`: only meaningful with the corpus.
- `maxCompatibility*` limits: same.
- `npm run compatibility` in `verify` and CI: same.
- `docs/compatibility-corpus.md`, `docs/black-signal-adoption-gap-audit.md`:
  migration documents belonging with the migration.
- The threat-model and versioning edits on those branches were re-derived
  against the new architecture rather than cherry-picked, because the file
  boundaries they describe no longer exist.

## Consequences

- Core gains one 35-line helper and one test file.
- The package smoke test is meaningfully stronger.
- Anyone doing the BLACK SIGNAL migration must fetch
  `origin/codex/package-compatibility-fixture` for the corpus; it is not lost,
  it is not merged. This ADR is the pointer.
