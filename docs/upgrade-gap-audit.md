# 0.2 upgrade gap and risk audit

Baseline reviewed: `67d73ab` on 2026-07-27. This audit is a delivery gate, not a certification report.

**Historical.** This audit describes the 0.2 hardening pass and its file layout,
before the 0.3 split into core plus lifecycle modules. Every item below was
closed in 0.2; the layer names it uses (`src/protocol`, `src/serialization`,
`src/reference`) are now deprecated aliases. See
[`architecture.md`](architecture.md) for the current layout.

| Priority | Gap / risk                                                                                                                                                                    | Required closure                                                                                                                                                   |
| -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| P0       | Commitments use delimiter-joined strings, so unescaped IDs and labels can produce ambiguous encodings.                                                                        | Length-prefixed canonical binary encoding, a new proof version, frozen legacy verification fixtures, and cross-domain collision tests.                             |
| P0       | The CLI casts arbitrary JSON to `Transcript`; malformed BigInts, fields, versions, and oversized payloads are not validated.                                                  | Bounded parser, explicit schema, migration rules, typed verification failures, and hostile-input tests.                                                            |
| P0       | Idempotency is keyed only by caller string. Reusing a key for a different action or payload returns the earlier receipt.                                                      | Bind key to canonical command fingerprint and reject mismatches with `IDEMPOTENCY_CONFLICT`.                                                                       |
| P0       | Re-entry resets `originalStake`, enabling a cap-basis change after liquidation.                                                                                               | Preserve the first entry's cap basis for the entire round/continuation chain and add a regression.                                                                 |
| P0       | Contingent payout is floored at entry rather than retained exactly until a payable credit boundary.                                                                           | Store a rational claim; round and cap only on liquidation or settlement.                                                                                           |
| P1       | Frame revision and action/ledger revision are the same counter; actions make unchanged prices stale and there is no evidence-frame transition.                                | Separate monotonic frame and ledger revisions and serialize both.                                                                                                  |
| P1       | `Posterior`, rational, adapter, continuation, outcome, label, and evidence limits are only partially checked.                                                                 | Exhaustive, bounded runtime validation with stable paths and typed codes.                                                                                          |
| P1       | Public exports expose all implementation modules through one barrel with no declared API or adapter version.                                                                  | Versioned public surface and explicit package subpath exports; keep internal helpers unreachable.                                                                  |
| P1       | There is no JSON-safe state/transcript/receipt format, migration policy, reconnect snapshot, or deterministic command replay.                                                 | Canonical serialization schemas, v1-to-v2 transcript migration, round snapshots, and replay fixtures.                                                              |
| P1       | `verifyTranscript` returns only boolean, collapsing unsupported version, malformed input, adapter mismatch, derivation failure, transcript mismatch, and commitment mismatch. | Structured verification result and compatibility boolean wrapper.                                                                                                  |
| P1       | The existing invariance test is small and not independent of engine arithmetic; accounting and cap monotonicity are not proved by tests.                                      | Independent oracle fractions, exhaustive schedules, deterministic property/metamorphic seeds, accounting conservation, boundary BigInts, and mutation regressions. |
| P1       | Stress creates 200 fresh books and races duplicate opens, but does not advance evidence, reconnect, re-enter, tamper, or measure tail latency/memory.                         | Seeded real-path workload, p50/p95/p99, throughput, heap/serialized-size bounds, schema validation, and non-flaky thresholds.                                      |
| P2       | Only two adapters exist and no reusable conformance runner protects future adapters.                                                                                          | Mechanical conformance report plus a minimal third fixture and malformed-adapter corpus.                                                                           |
| P2       | CI is one Node version without coverage, conformance, package smoke, checked artifact schemas, or a security-specific test command.                                           | Node matrix, bounded coverage gate, conformance/fuzz/stress/package/security jobs, and artifact upload.                                                            |
| P2       | Documentation is too short to define compatibility, integration accounting, attack vectors, release policy, or exact evidence limits.                                         | Expand API/reference, versioning, integration checklist, threat model, math assumptions, changelog, and evidence ledger.                                           |

## Completion rules

- Every P0/P1 item must have executable regression evidence.
- Synthetic load figures remain local/CI engineering evidence, never production-capacity or certification claims.
- BLACK SIGNAL remains a compatibility adapter only; no title assets, narrative, compliance copy, or UI enter the engine.
- The repository stays private, proprietary, and `UNLICENSED`; no package publication is authorized.
